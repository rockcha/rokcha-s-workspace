# 구글 드라이브 파일 연결

별도 **자료실** 메뉴에서 **기존 파일 찾기**로 드라이브 파일을 탐색하거나 **파일 업로드**로 컴퓨터의 파일을 드라이브에 올립니다. 구글 로그인 → 선택 또는 업로드 → 제목·설명 확인 → 저장 순서입니다. 등록한 카드는 원본을 새 탭으로 열고, 다운로드 버튼으로 파일을 내려받습니다. 파일 자체는 드라이브에 남고 자료실 전용 테이블에는 제목·주소·설명과 폴더 구조를 저장합니다. 자료실 목록에서 제거해도 드라이브 원본은 삭제되지 않습니다. 파일 공유 권한은 바뀌지 않으므로 다른 계정에서 열 때는 원본 접근 권한이 필요합니다.

## 설정

같은 Google Cloud 프로젝트에서 Google Drive API와 Google Picker API를 활성화하고, Google Auth Platform에 앱 정보와 외부/테스트 사용자 설정을 완료합니다. 테스트 사용자에는 실제 드라이브 계정을 추가합니다. OAuth 웹 클라이언트의 승인된 JavaScript 원본에는 실제 개발 주소(예: `http://localhost:5173`)를 등록합니다. 경로나 `/*`는 넣지 않습니다. 브라우저 팝업 방식이므로 리디렉션 URI와 Client Secret은 사용하지 않습니다.

루트 `.env.local`의 기존 설정 아래에 다음 세 항목을 추가하고 개발 서버를 다시 시작합니다.

```dotenv
VITE_GOOGLE_CLIENT_ID=YOUR_CLIENT_ID.apps.googleusercontent.com
VITE_GOOGLE_APP_ID=YOUR_NUMERIC_PROJECT_NUMBER
VITE_GOOGLE_API_KEY=YOUR_PICKER_API_KEY
```

이 브라우저용 API 키는 빌드에 포함됩니다. API 제한은 Google Picker API, 웹사이트 제한은 실제 앱 주소(예: `http://localhost:5173/*`)와 `https://docs.google.com/*`로 설정합니다. 서비스 계정 키나 Client Secret을 VITE 변수에 넣지 않습니다. `.env.local`은 커밋하지 않습니다.

배포 시 호스팅 서비스에도 세 환경 변수를 등록하고 다시 빌드합니다. 배포 주소를 OAuth 원본과 API 키 웹사이트 제한에 각각 추가합니다. 로컬 설정만으로 배포 환경이 변경되지는 않습니다. **supabase/materials.sql을 SQL Editor에서 한 번 실행해야 합니다.** 기존 접속 SQL은 다시 실행하지 않습니다. 서버 함수 배포는 필요하지 않습니다.

## 동작과 문제 해결

- Google Identity Services와 Picker 스크립트를 자료실에서 준비한 뒤 버튼 클릭으로 인증 창을 엽니다. `drive.file` 권한을 요청하며 선택한 파일을 연결합니다. 기존 파일 탐색은 Google Picker에서 제공하며, 자료실에는 등록한 자료 목록이 표시됩니다. 전체 드라이브 자동 동기화는 하지 않습니다. 업로드는 Google Picker의 DocsUploadView를 사용하고 드라이브 용량을 사용합니다.
- 접근 토큰은 파일 선택창에만 전달하며 DB·브라우저 저장소에 보관하지 않습니다. 파일 선택을 다시 시작할 때 새 인증 요청을 합니다. 페이지를 나가면 선택창을 정리하고 늦은 응답을 무시합니다.
- 팝업이 막혔으면 해당 사이트의 팝업을 허용하고 버튼을 다시 누릅니다. 거절·취소 시 자료 목록에는 등록하지 않습니다. 업로드 완료 후 등록을 취소해도 드라이브 파일은 유지됩니다.
- `origin_mismatch`는 실제 주소의 프로토콜·호스트·포트와 OAuth 원본이 같은지 확인합니다. `localhost`와 `127.0.0.1`은 서로 다른 원본입니다.
- Picker 키 오류는 같은 프로젝트의 API 키·프로젝트 번호인지, Picker API 활성화와 `docs.google.com` 웹사이트 제한을 확인합니다.
- 저장 실패 시 자료 저장창에 선택 결과를 유지합니다. 저장 성공은 자료실 토스트 한 번으로 표시합니다.
- 브라우저 자동 테스트는 가짜 Google SDK와 로컬 테스트 DB를 사용합니다. 실제 계정의 로그인·파일 선택은 로컬에서 직접 확인해야 합니다.

참고: [Google Picker](https://developers.google.com/workspace/drive/picker/guides/web-picker), [브라우저 인증](https://developers.google.com/identity/oauth2/web/guides/use-token-model).

자료실은 링크함과 별도 저장소입니다. 이전에 링크함에 등록한 드라이브 링크는 그대로 유지되며, 자료실의 기존 파일 찾기에서 다시 등록할 수 있습니다. 같은 드라이브 파일을 다시 등록하면 자료실 항목을 갱신하여 중복을 방지합니다.

## 폴더와 다운로드

최신 `supabase/materials.sql`을 SQL Editor에서 다시 실행하면 `material_folders`와 자료의 `folder_id`가 추가됩니다. 기존 자료는 최상위에 유지됩니다. 이 SQL은 재실행할 수 있으며 접속 SQL은 다시 실행하지 않습니다.

자료실에서는 폴더·하위 폴더 생성, 폴더 이름 수정, 폴더 경로 탐색을 지원합니다. 자료 저장·수정 창의 폴더 선택기로 위치를 지정합니다. 검색은 현재 폴더의 자료에 적용됩니다. 폴더 삭제 시 하위 폴더도 삭제하지만 포함 자료는 최상위로 옮깁니다. 드라이브 원본과 드라이브의 실제 폴더 구조는 변경하지 않습니다. 자료실 폴더는 작업실 세션으로 접근하는 공용 정리 구조입니다.

자료 카드 클릭은 드라이브 원본을 새 탭으로 엽니다. 다운로드 버튼은 브라우저의 구글 로그인 상태로 드라이브 다운로드 주소를 엽니다. 일반 파일은 원본을, Google 문서는 PDF, 스프레드시트는 Excel, 프레젠테이션은 PowerPoint, 그림은 PNG로 다운로드합니다. 원본 URL의 resourcekey가 있으면 보존합니다. 파일 권한·로그인·대용량 파일에 따라 Google 확인 화면이 나올 수 있습니다. 다운로드 완료 여부는 앱에서 확인하지 않으며 성공 토스트를 표시하지 않습니다.
